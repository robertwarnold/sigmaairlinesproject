## Generator methodology

The deterministic inventory expands explicit quantities to separate physical unit IDs. It records source section locators and labels explicitly named table interfaces. For narrative-only interfaces, functions, operating states, dependencies, redundancy and equivalence, the generator flags gaps and accepts independently prepared input-only inventory facts. The extraction program does not certify narrative completeness. The unchanged source packages and scoring scale remain the basis.

The official response requires `standalone-fmea-v4.0-response-2`. Each candidate has a stable row ID, inventory unit, case, operating context, local effect, higher-level effect, system effect, and a severity rationale. Prevention and detection statements tie back to the inventory. Unsupported ratings may be null, so their RPN remains empty. A numeric severity requires a rationale. The legacy CSV fields remain first, with V4 traceability fields appended. Old V4 artifacts remain readable for provenance. The generation path requires the current response contract.

Each response receives one deterministic local quality pass for repeated-unit coverage, all case links, independent applicability, propagation gaps, exact duplicates, potential overlaps, assumptions and severity-review flags. Structural errors reject the official CSV. Heuristic flags preserve candidate rows and call for engineering review. No automatic follow-up request, silent consolidation or inferred engineering approval occurs. The receipt hashes the raw response, accepted CSV when available, and `*_diagnostics.json`. A failed or truncated run still receives an execution receipt and diagnostic export when local output storage is available. The workflow uploads the extra artifact alongside the existing single-run bundle. Synchronization verifies its digest.

## Dashboard and compatibility

The five-view dashboard retains V4.5 navigation and filters. Quality separates the selected historical comparison from published version-specific missed-reason evidence. Generator self-check counts sit in individual experiment details and have a separate scope from independent judge coverage. Failures count in completed execution denominators and stay outside successful timing summaries. The sensitivity graph varies annual workload and review and reconstruction hours in the existing financial comparison formula, with an exact-value table and break-even quantities. The private Explorer adds explicit adjudication language and shows higher-level effects and severity rationale where present. Existing disposition codes and append-only history remain compatible.

The registry binds official judge records to the exact release receipt. It rejects pooling development and release V4.0 records in one analyzed cohort. The V1.2 identifier-only judge contract remains unchanged. Historical V2/V3 reports and original receipts remain isolated from new validation. No confidential reference text is included in this release.
